# both reported. When a keyword is made usable, delete its line.
#

# KeywordAsIdentifierCorpusTests.ReportEveryKeywordAsAColumnNameTest.
#
# ---------------------------------------------------------------------------------------------------
# THE ORACLE VERDICT, and it splits this file in two.
#
# The same 172 names were put to SQLite as `CREATE TABLE t (<Name> TEXT)`:
#
#   * 118 of them SQLite ACCEPTS. Those are a real drop-in gap - see section A below - and they
#     include utterly ordinary column names: Text, Int, Decimal, Double, Char, Money, Json, Guid,
#     Row, Start, End, Current, Timestamp, View, Column, Interval, Partition, Sequence.
#   * 54 of them SQLite REJECTS too. Those are the genuinely reserved words, and WitSQL refusing them
#     is CORRECT - PostgreSQL and SQL Server refuse them as well. See section B.
#
# So the finding is "118 keywords", not "172". Recorded rather than fixed: phase 5's remit is
# concurrency, KEY was fixed because it was the one the phase tripped over, and a 118-keyword grammar
# change is its own piece of work with real ambiguity risk - most of section A is TYPE names, so
# `CREATE TABLE T (Text TEXT)` asks the parser to take a type keyword as a column name immediately
# before a type keyword. Handed to phase 7 (schema and DDL fidelity), where the DDL round-trip corpus
# lives.
# ---------------------------------------------------------------------------------------------------
